# Спецификация: Telegram-бот с локальной LLM (Ollama)

Основано на требованиях из [`promt.md`](./promt.md).

## 1. Назначение

Telegram-бот, работающий на локальной машине пользователя. Принимает текстовое
сообщение, пересылает его как запрос в локально запущенную LLM (через Ollama),
и возвращает ответ модели пользователю в чат. История переписки не хранится —
каждое сообщение обрабатывается независимо (stateless, one-shot).

## 2. Технологический стек

- **Язык/рантайм:** Node.js (JavaScript, без TypeScript).
- **Telegram Bot API:** только нативные HTTP-запросы (`fetch`/`https`), без
  сторонних библиотек (`node-telegram-bot-api`, `telegraf` и т.п. — под запретом).
- **Получение обновлений:** long polling через метод `getUpdates`
  (без вебхуков — упрощает локальный запуск без публичного HTTPS-адреса).
- **LLM backend:** Ollama HTTP API (`http://localhost:11434` по умолчанию),
  доступ через слой абстракции (см. п. 4).
- **Конфигурация:** `.env`-файл, загружаемый через `process.loadEnvFile()`
  (Node.js ≥ 20.6, без пакета `dotenv`) либо через `dotenv`, если версия Node
  ниже — решить на этапе реализации в зависимости от доступной версии Node.
- **Зависимости:** минимальные; в идеале — ноль npm-зависимостей, только
  встроенные модули Node.js.

## 4. Абстракция LLM-runner'а

Требование ТЗ — заложить возможность подключать другие локальные LLM-раннеры
(LM Studio, llama.cpp server, и т.д.), не переписывая логику бота.

### Контракт (`src/llm/LlmRunner.js`)

Каждый runner — объект/класс с единым асинхронным методом:

```js
/**
 * @typedef {Object} LlmRunner
 * @property {(prompt: string) => Promise<string>} generate
 *   Отправляет prompt в LLM и возвращает текст ответа.
 *   Не хранит и не использует историю — каждый вызов независим.
 */
```

### Реализация Ollama (`src/llm/OllamaRunner.js`)

- Использует эндпоинт `POST /api/generate` (или `/api/chat` с одним сообщением
  `user` — выбрать `/api/generate` как более простой для one-shot сценария).
- Параметры: `model` (из `.env`, например `OLLAMA_MODEL`), `stream: false`
  (без потоковой генерации — упрощает интеграцию с Telegram, где ответ
  отправляется одним сообщением).
- Базовый URL Ollama берётся из `.env` (`OLLAMA_BASE_URL`, по умолчанию
  `http://localhost:11434`).
- Ошибки сети / недоступности Ollama — пробрасываются наверх с понятным
  сообщением, чтобы `messageHandler` мог отправить пользователю
  человекочитаемую ошибку вместо падения процесса.

### Фабрика (`src/llm/index.js`)

- Читает `LLM_PROVIDER` из конфига (`ollama` по умолчанию).
- Возвращает соответствующий runner. Добавление нового провайдера в будущем —
  это новый файл `src/llm/<Provider>Runner.js` + одна ветка в фабрике, без
  изменений в `messageHandler` и `polling`.

## 5. Работа с Telegram Bot API (без сторонних библиотек)

### `src/telegram/client.js`

Минимальный клиент поверх `fetch`:

- `getUpdates({ offset, timeout })` → `GET/POST https://api.telegram.org/bot<TOKEN>/getUpdates`
  - Использовать long polling: `timeout` ~30 сек на стороне Telegram.
- `sendMessage({ chatId, text })` → `POST https://api.telegram.org/bot<TOKEN>/sendMessage`
  - Разбивать длинные ответы модели на части, если текст превышает лимит
    Telegram в 4096 символов на сообщение.

### `src/telegram/polling.js`

- Бесконечный цикл: запрос `getUpdates` с `offset = last_update_id + 1`,
  обработка каждого текстового сообщения через `messageHandler`, обновление
  `offset`.
- Обработка ошибок сети — retry с небольшой задержкой, без падения процесса.
- Игнорировать не-текстовые сообщения (стикеры, фото и т.д.) — либо не
  отвечать, либо отвечать коротким пояснением («Я понимаю только текст»,
  решить при реализации — не критично для MVP).

## 6. Поток обработки сообщения (`src/handlers/messageHandler.js`)

1. Получено текстовое сообщение → `{ chatId, text }`.
2. Вызов `llmRunner.generate(text)`.
3. При успехе — `telegramClient.sendMessage({ chatId, text: response })`.
4. При ошибке (LLM недоступна, таймаут и т.п.) — отправить пользователю
   сообщение об ошибке, залогировать причину в консоль на сервере.
5. Никакого состояния между вызовами не сохраняется — обработчик не хранит
   ссылок на предыдущие сообщения пользователя.

## 7. Конфигурация и безопасность

### `.env.example` (коммитится в репозиторий)

```
TELEGRAM_BOT_TOKEN=
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3
```

### `.env` (в `.gitignore`, реальные значения)

### `.gitignore`

Должен содержать как минимум:

```
.env
node_modules/
```

### `src/config.js`

- Читает и валидирует переменные окружения при старте.
- Если `TELEGRAM_BOT_TOKEN` не задан — процесс завершается с понятной
  ошибкой при старте (fail fast), а не при первом сообщении пользователя.

## 8. Обработка ошибок и логирование

- Все ошибки (сеть Telegram, сеть Ollama, некорректный ответ модели)
  логируются в `stdout/stderr` с достаточным контекстом (chatId, время,
  текст ошибки — но не сам токен бота).
- Бот не должен падать из-за единичной ошибки обработки одного сообщения —
  цикл polling продолжает работу.

## 9. README.md (`telegram-bot/README.md`)

Отдельный README внутри `telegram-bot/` с инструкцией по запуску проекта.
Обязательные разделы:

- **Описание** — коротко, что делает бот (1–2 предложения).
- **Требования** — версия Node.js, установленный и запущенный Ollama
  (с ссылкой на https://ollama.com), скачанная модель (например
  `ollama pull llama3`).
- **Установка** — `npm install`.
- **Настройка** — скопировать `.env.example` в `.env`, заполнить
  `TELEGRAM_BOT_TOKEN` (как получить токен через @BotFather — короткая
  инструкция), при необходимости изменить `OLLAMA_MODEL`/`OLLAMA_BASE_URL`.
- **Запуск** — `npm start` (или `node src/index.js`), что ожидать в консоли
  при успешном старте.
- **Проверка работы** — найти бота в Telegram по имени, отправить текстовое
  сообщение, получить ответ.
- **Возможные проблемы** — что делать, если Ollama не запущена/недоступна,
  если токен неверный, если модель не скачана.
- **Расширение LLM-провайдеров** — кратко: как добавить новый runner
  (создать `src/llm/<Provider>Runner.js`, зарегистрировать в фабрике,
  указать `LLM_PROVIDER` в `.env`).

## 10. Явно вне рамок (out of scope) для MVP

- Хранение истории диалога / контекста.
- Аутентификация/белый список пользователей.
- Поддержка не-текстовых сообщений (голос, изображения).
- Вебхуки (используется только long polling).
- Стриминг ответа модели по частям в Telegram.
- Docker/деплой на сервер — бот запускается локально (`node src/index.js`).

## 11. Критерии готовности (Definition of Done)

- [ ] `npm install && cp .env.example .env` → заполнить токен → `npm start`
      запускает бота без ошибок при поднятом локально Ollama.
- [ ] Текстовое сообщение в Telegram → бот отвечает результатом генерации
      модели Ollama.
- [ ] Отправка нескольких сообщений подряд не путает контекст (каждый ответ
      независим от предыдущих).
- [ ] `.env` не закоммичен в git; токен нигде не захардкожен в исходниках.
- [ ] Смена `LLM_PROVIDER`/добавление нового runner'а не требует правок в
      `telegram/*` и `handlers/*`.
- [ ] Ollama недоступна → бот присылает сообщение об ошибке, а не падает.
- [ ] `telegram-bot/README.md` содержит все разделы из п. 9 и по нему
      можно запустить проект с нуля, не заглядывая в код.
