# Telegram-адаптер Core Orchestrator

Тонкий адаптер между Telegram и [Core Orchestrator](../core): принимает
сообщения пользователей, передаёт их в Core и отправляет обратно в чат готовые
ответы, которые Core доставляет на callback-эндпоинт адаптера.

```
Telegram ──► адаптер ──POST /v1/.../messages──► Core ──► LLM
                ▲                                 │
                └────POST /callbacks/replies──────┘
                     (когда ответ готов)
```

Ни модели, ни базы данных здесь нет: история диалогов, контекстное окно, учёт
токенов и обращение к LLM — целиком на стороне Core. Внешних зависимостей у
адаптера тоже нет, только встроенные модули Node.js, поэтому `npm install`
не требуется.

Обмен асинхронный. Core отвечает `202 { jobId }` сразу, не дожидаясь модели, —
генерация занимает десятки секунд, и держать соединение всё это время незачем.
Готовый ответ приходит отдельным запросом на локальный callback-сервер
адаптера.

## Требования

- Node.js 18 или выше.
- Запущенный Core Orchestrator — см. [`../core`](../core) и
  [корневой README](../README.md).
- Токен бота от [@BotFather](https://t.me/BotFather).

## Настройка

```bash
cp .env.example .env
```

Обязательна ровно одна переменная — `TELEGRAM_BOT_TOKEN`. Получить его: откройте
чат с [@BotFather](https://t.me/BotFather), отправьте `/newbot`, следуйте
инструкциям; в ответ придёт токен вида
`123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

Остальное имеет рабочие значения по умолчанию; полный список с пояснениями —
в [`.env.example`](./.env.example). Что стоит знать:

- `CORE_BASE_URL` — адрес Core. В compose это имя сервиса (`http://core:8080`),
  при локальном запуске — `http://localhost:8080`.
- `CORE_AUTH_TOKEN` — общий с Core секрет. Подписывает исходящие запросы и
  проверяется на входящих callback'ах, чтобы бот не отправил пользователю
  «ответ модели» от постороннего источника. Значение должно **совпадать** с
  `CORE_AUTH_TOKEN` в `core/.env`; пустое значение отключает проверку — так
  можно только локально.
- `CALLBACK_PORT`, `CALLBACK_PATH` — где адаптер слушает ответы от Core.
  Должны соответствовать `ADAPTER_TELEGRAM_CALLBACK_URL` в конфигурации Core.
- `MAX_MESSAGE_LENGTH` — предел длины сообщения от пользователя в символах
  (по умолчанию 1000). Длиннее — отклоняется с предупреждением, не доходя до
  Core.

## Запуск

Сначала должен быть поднят Core, иначе первые сообщения упрутся в недоступный
сервис.

```bash
npm start
```

При успешном старте в консоли появится:

```
Бот запущен, ожидание сообщений...
```

Остановить — `Ctrl+C`: адаптер аккуратно досматривает текущий цикл опроса и
закрывает callback-сервер.

Запуск обоих сервисов сразу через `docker compose` описан в
[корневом README](../README.md) — это рекомендуемый способ.

## Команды бота

Зарегистрированы в меню Telegram (кнопка «/» рядом с полем ввода):

- `/new` — начать новый диалог, сбросив контекст;
- `/start` — приветствие и начало нового диалога;
- `/help` — краткая справка.

Добавить команду можно одной записью в реестре `src/handlers/commands.js` —
меню и обработчик берутся оттуда же, поэтому разъехаться не могут.

## Что видит пользователь

Формулировки живут в адаптере, а не в Core, — Core присылает машиночитаемый код
причины, а как это назвать, зависит от канала: веб-адаптеру фраза про «команду
/new» не подошла бы.

- **Форматирование.** Модели обычно отвечают в Markdown. Перед отправкой
  адаптер конвертирует его в HTML-подмножество, которое Telegram умеет
  рендерить при `parse_mode=HTML` (`src/telegram/markdown.js`), — сообщение
  приходит с настоящим жирным шрифтом, курсивом, моноширинным кодом и
  кликабельными ссылками. Если разметка окажется некорректной и Telegram
  откажется её парсить, сообщение не теряется: отправка повторяется без
  `parse_mode`.
- **Контекст заполнен** (`context_limit`). Пользователь получает просьбу начать
  новый диалог командой `/new` с указанием, сколько токенов израсходовано. Если
  контекст заполнился ровно тем ответом, который только что пришёл,
  предупреждение отправляется сразу за ним — чтобы следующий вопрос не упёрся
  в отказ без объяснений.
- **Модель не успела ответить** (`llm_timeout`) — предложение повторить вопрос
  или сформулировать его короче.
- **Прочие ошибки обращения к модели** — общее сообщение с предложением
  попробовать позже.

Ошибки отправки в Telegram намеренно не гасятся: callback-сервер возвращает
Core ошибку, и тот повторяет доставку. Иначе ответ, на который модель потратила
десятки секунд, терялся бы из-за одной сетевой неудачи.

## Ограничения

- **Только текстовые сообщения.** Фото, документы, голосовые, стикеры и прочие
  вложения не обрабатываются: пользователь получает предупреждение, запрос в
  Core не уходит.
- **Лимит длины сообщения.** Длиннее `MAX_MESSAGE_LENGTH` символов — отклонение
  с предупреждением, без обращения к Core. Меняется в `.env`, без правок кода.

## Тесты

```bash
npm test
```

Встроенный `node --test`, тестовых зависимостей нет. Покрыты конвертер
Markdown, клиент Core, callback-сервер, обработчик ответов, реестр команд,
клиент Telegram и цикл polling. Сеть, Telegram и Core заменяются локальными
заглушками, поэтому ни токена, ни запущенного Core для тестов не нужно.

## Проверка работы

1. Найдите бота в Telegram по username, указанному при создании в BotFather.
2. Отправьте любое текстовое сообщение.
3. Адаптер передаст его в Core и пришлёт ответ модели в чат.

## Возможные проблемы

- **«Отсутствует обязательная переменная окружения TELEGRAM_BOT_TOKEN»** — не
  заполнен `.env`.
- **«Сервис временно недоступен»** — адаптер не достучался до Core. Проверьте
  `CORE_BASE_URL` и что Core запущен и здоров (`GET /health`, в compose —
  `docker compose ps`).
- **Core отвечает 401** — не совпадают значения `CORE_AUTH_TOKEN` в двух `.env`.
- **Ответы не приходят, хотя Core их сформировал** — Core не может достучаться
  до callback-эндпоинта. Сверьте `CALLBACK_PORT`/`CALLBACK_PATH` с
  `ADAPTER_TELEGRAM_CALLBACK_URL` в `core/.env`. В логах обоих сервисов
  фигурирует один и тот же `jobId` — по нему удобно сопоставлять записи.
- **Бот не отвечает в Telegram** — проверьте, что токен скопирован без лишних
  пробелов и что у процесса есть доступ в интернет.

Проблемы, связанные с моделью («не удалось подключиться к Ollama», пустые или
странные ответы), относятся к Core — см. [корневой README](../README.md).
